## 6. Open decisions (owner call — presented, not decided)

* **DESIGN-1 — tuned springs vs constant-duration rule.** `games/constants.ts:99-101`
  and `GamesProgressControls.tsx:22,252` use configured (stiffness/damping) springs; the
  stack rule says motion must use constant durations / never default springs. **For
  tuned springs:** the carousel's physical, Apple-like feel depends on spring physics;
  converting to `cubic-bezier` + duration re-tunes (and risks degrading) motion that
  took real iteration to get right. **For the rule:** consistency and predictability of
  the motion system; springs make duration content-dependent. Options: (a) amend the
  rule to permit *explicitly tuned* (never default) springs — codifies current reality;
  (b) convert the carousel to durations — rule-pure, needs careful re-tuning and a
  browser pass. Recommendation from the baseline stands as (a), but this is an owner
  decision; unresolved.
* **DP-13 — footer landmark** adds visible UI: design decision, not a mechanical fix.
* **SEC-5 — HSTS preload** needs a one-time owner submission at hstspreload.org.

## 8. Notes & caveats (anti-sycophancy)

* **Turbopack suppresses the First Load JS table**, so lane 2 measured chunk gzip sizes
  directly; the baseline's "~245 KB gz First Load" figure is not directly comparable —
  treat 71.3 KB (framer) + 71.0 (react-dom vendor) + 49.2 + 39.5 (next) as the current
  ground truth.
* **NEW-1/NEW-2 may be intentional design** ("match pointer hit areas to visible
  bounds"). The finding is not that the commit is wrong, but that it trades tap-target
  size to the WCAG 2.5.8 floor without documentation or tests. Wave 1 proposes keeping
  the visual intent while restoring the interactive surface — owner may instead accept
  and document the current targets.
* **Coverage percentage (17.8%) is not a vanity target**: per the coverage-integrity
  rule, framework shells were deliberately skipped at baseline. The actionable gap is
  the *behavioral* surface (nav/menu/carousel), not the number.
* **This audit changed no product code.** Only this report and one decision-log entry
  were written; build artifacts (`.next/`, `coverage/`) produced during verification are
  gitignored.
